Understanding Decorators

In Python, a decorator is a design pattern that allows a user to add new functionality to an existing object without modifying its structure. Decorators are usually called before the definition of a function you want to decorate.

functions First-Class Citizens

Functions in Python are objects; they can be passed as arguments, returned from other functions, and assigned to variables.

data_object Closure Support

Decorators leverage closures to "remember" the function they are wrapping and the scope in which they were created.

The Basic Syntax

Think of a decorator as a wrapper. It takes a function, performs some action before and after that function is executed, and then returns the original or a modified version of that function. The @decorator_name syntax is simply syntactic sugar for func = decorator(func).

timer_decorator.py 
import time

def timer(func):
    """A decorator that prints the execution time."""
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"{func.__name__} took {end_time - start_time:.4f}s")
        return result
    return wrapper

@timer
def complex_calculation():
    # Simulate heavy workload
    time.sleep(1)
    return "Success"

complex_calculation()

Why use decorators?

  • bolt DRY Principle: Avoid code duplication for logging, caching, and authentication.
  • bolt Separation of Concerns: Keep business logic clean and separate from metadata tasks.
  • bolt Extensibility: Easily add functionality to third-party library functions.
